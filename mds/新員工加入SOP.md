# 新員工加入系統 SOP

> 新員工要能完整使用系統，需開通**兩道門**。少一道就會卡：登不進、或登進去資料讀不到。
> 假設新員工信箱為 `xxx@gmail.com`，用你的 owner 帳號操作。
>
> **2026-07-30 起系統與 Google 行事曆完全分家**：登入改成**信箱＋密碼**、課表全在系統資料庫裡。
> 原本的「門 1 Google 登入許可」與「門 3 行事曆共用」都取消了。

---

## 門 1：建帳號並設密碼（Firebase Authentication）

不開 → 登入頁按登入會說「信箱或密碼不對」。

1. 打開 https://console.firebase.google.com/project/hobe-494909/authentication/users
2. 「**新增使用者**」→ 填 `xxx@gmail.com` ＋ 一組暫時密碼 → 新增
3. ⚠️ **一定要接著做**：在那筆使用者右邊 **⋮ → 重設密碼**，把連結／信交給新員工，讓他**自己點連結設定密碼**
   - 為什麼不能跳過：Console 直接建的帳號 `email_verified` 是 **false**，會被門 2 的規則擋在外面（登得進去但看不到任何資料）。走完重設密碼的信才會變 true
4. 新員工到登入頁填信箱＋密碼即可（也可以自己在登入頁按「第一次登入／忘記密碼？寄設定密碼信」）

## 門 2：資料庫白名單（Firestore）

不開 → 能登入，但學生／課程／補課資料全讀不到，跳「此帳號未獲授權」。

1. 編輯本專案 [`firestore.rules`](../firestore.rules)，在 email 白名單加一行 `xxx@gmail.com`（注意逗號）
2. 打開 https://console.firebase.google.com/project/hobe-494909/firestore/rules
3. 把整份規則貼上 → 先用「Rules Playground」測 allow/deny → 按「**發布**」
4. （順手）把 `firestore.rules` 的改動 commit 留底

## 門 3（規劃中，功能還沒做）：練習課考卷 Drive 資料夾

> **狀態（2026-07-03）**：練習課「考卷檔案上傳」還在設計階段（方案見 [`進展紀錄.md`](進展紀錄.md) 2026-07-03），這道門**現在不用做**，等功能上線後把本段填成具體步驟。

規劃中的方案是「上傳進專用資料夾 → 檔案設連結可檢視 → 連結存資料庫」，對新員工的影響預計是：

- **只看/列印考卷**的員工：**不用開任何門**（點系統裡的連結就能看）
- **要上傳考卷**的員工：需把考卷專用 Drive 資料夾共用給 `xxx@gmail.com`（權限「編輯者」），讓他傳的檔案進同一個資料夾

## 常見卡點

- **登得進去但每一頁都空、跳「此帳號未獲授權」**：門 2 白名單沒加，或門 1 只建了帳號沒走「重設密碼」的信（`email_verified` 還是 false）。
- **「Firebase 尚未啟用電子郵件/密碼登入方式」**：到 Authentication → 登入方式 把「電子郵件/密碼」啟用。
- **診斷**：系統頁面 F12 → Console 輸入 `firebase.auth().currentUser`，看 `email` 對不對、`emailVerified` 是不是 `true`。

## 帳號管理備註

- **登入方式只留「電子郵件/密碼」**：Authentication → 登入方式裡，Google 是過渡期備援（全員設好密碼後停用）、**匿名要保持停用**（系統沒用到，開著等於多一道沒必要的門）。
- **離職**：Firebase Authentication → 使用者 → ⋮ → 停用或刪除帳號，並把 `firestore.rules` 白名單那行刪掉重新發布。兩邊都要做。
